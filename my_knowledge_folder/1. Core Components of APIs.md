
To understand how web APIs work, it helps to break them down into their core components. Every interaction with an API involves sending a request to a specific URL- called an endpoint- and receiving a response.

- **Core API Components:**
    - **Endpoints:** URLs that represent data or services
    - **HTTP Methods:** Actions like GET, POST, PUT, and DELETE
    - **Requests and Responses:** How data is sent to and received from an API
    - **Status Codes:** Indicators of whether a request succeeded or failed

---

**1. Endpoints**

An **endpoint** is a specific URL that represents a resource or service. It is the HTTP address to which user send an API request to access or modify something.

For example, API request is send with the endpoint 123 where it is function of hheheh the weather forecast data for a location. Each endpoint is part of the overall structure of an API and typically maps to a specific function or piece of data.

For example, an endpoint like `https://myurl.com/tasks` might return all tasks, while `https://myurl.com/tasks/1` could return just the task with `ID 1`. Endpoints are usually organized by resource type and follow predictable patterns, making APIs easier to navigate and use.

---

**2. HTTP Methods**

https://learning.postman.com/docs/use/send-requests/requests/#common-http-methods

**HTTP methods** define the type of action you want to perform when interacting with an endpoint. They tell the API how to handle your request. The most common methods include:

|Method|Action|Example|
|---|---|---|
|GET|Retrieve data|Get a list of tasks|
|POST|Submit new data|Create a new task|
|PUT|Update existing data|Mark a task as complete|
|DELETE|Remove data|Delete a task|

Together, the endpoint tells you what you're interacting with, and the method tells you how you're interacting with it.

---

**3. Request

https://learning.postman.com/docs/use/send-requests/requests/

A **request** is a message sent to an API to ask for data or perform an action. In production, this is usually sent by another application or service. During development, tools like Postman help you build and test requests manually.

Every request includes a few key parts:

- An **endpoint** (the URL you’re sending the request to)
- An **HTTP method** (what action you want to take, like GET or POST)
- Optional headers, parameters, or a body, depending on what the API needs

Using the task tracking API as an example, if you’re creating a new task, you’d send a POST request to `/tasks` endpoint with the task details in the request body.

**4. Response**

https://learning.postman.com/docs/use/send-requests/response-data/responses/

After you send a request, the API sends back a **response**. This response includes:

- A **status code** that tells you if the request succeeded (like 200 OK) or failed (like 404 Not Found)
- A **body** that contains the data returned by the API (usually in JSON format)
- Additional details in the **headers**, like content type or rate limit info

For example, if you send a request to GET /tasks, the response body might be a list of tasks.
